# Phase 4B-9D: Workbench QA Recipes & Demo Scenario Seeds

## Objective

Create reusable QA recipes and demo scenario scripts for the AI Workbench ecosystem after Phase 4B-9C.

The goal is to make future regression testing faster and more consistent across:

```text
Dataset Catalog
-> Relationship Set topic graph
-> AI planner candidate narrowing
-> AnalysisPlanCard
-> Prefill navigation
-> Analysis result handoff
-> SafeResultSummary
-> Result follow-up
-> Hermes dry-run opt-in safety
```

## Scope

This was a documentation-focused phase.

Allowed:

- create QA recipe documentation;
- create demo scenario documentation;
- document recommended demo datasets and expected catalog classifications;
- update current progress, changelog, roadmap, and README references.

Out of scope:

- product behavior changes;
- live Hermes/LLM integration;
- runtime behavior changes;
- backend fixtures;
- dataset mutation;
- SmartAnalysis changes;
- package or dependency changes.

## Implementation Summary

Added a reusable AI Workbench QA playbook covering:

- required local setup;
- recommended 10-file demo dataset set;
- expected catalog classification targets;
- Dataset Catalog search and grouped views;
- Relationship Set topic graph creation, high-risk edges, and isolated/reference tables;
- planner candidate narrowing;
- selected dataset priority;
- candidate vs required dataset display;
- prefill navigation;
- Context Panel states;
- result handoff from History and Statistics;
- deterministic result follow-up;
- default and opt-in Hermes dry-run safety;
- regression checklist and known limitations.

Added concise demo scripts for:

- Dataset Catalog -> Forecast plan;
- Relationship Set -> channel conversion plan;
- Result -> AI Workbench follow-up;
- safety regression checks.

Updated the documentation index and project progress docs to reference `docs/qa/`.

## QA Recipes Included

Dataset Catalog:

- search by filename/id/schema/catalog labels/analysis tags;
- group by default, upload day, upload week, business topic, data type, and analysis usage;
- verify dataset actions after filtering.

Relationship Set:

- create a topic graph with users/products/orders/events/marketing/quality datasets;
- confirm high-risk edge behavior;
- verify relationship sets do not become required dataset lists.

Planner:

- no selected dataset/no relationship set prompts;
- selected dataset priority prompts;
- candidate vs required display checks.

Navigation:

- Forecast, PathAnalysis, Attribution, and Statistics prefill;
- invalid prefill fallback;
- no target page auto-run.

Context and result flow:

- dataset, relationship, and history context states;
- lazy relationship previews;
- History and Statistics handoff;
- deterministic follow-up prompts.

Hermes:

- default local rule-based mode;
- explicit `hermes_dry_run` mode with fallback.

## Known Limitations

- The QA recipes are manual; no automated browser test suite was added.
- The recommended demo dataset set is documented but not generated by this phase.
- Exact catalog labels can vary when uploaded files have sparse schemas.
- Forecast, PathAnalysis, and Attribution direct result-to-Workbench buttons remain future work.
- Semantic/DataWorkshop prefill remains future work.
- Live Hermes remains a separately approved future phase.

## Next Recommended Phase

Add optional browser-based smoke scripts or a lightweight developer diagnostics checklist that can replay these QA recipes against a local seeded environment, while keeping live Hermes integration separate and explicitly approved.
